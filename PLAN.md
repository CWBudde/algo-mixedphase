# algo-mixedphase Roadmap

This repository grew out of Phase 42 of [algo-dsp](https://github.com/cwbudde/algo-dsp)
("Mixed-Phase FIR Design & Alternatives") and was split off so that the paper, the
comparison harness and the interactive lab can evolve on their own schedule, without
gating algo-dsp's v1.0.

## Goal

Build a reproducible comparison around the fixed-support alternating factorisation from
Christian-W. Budde's DAGA 2012 paper. Keep identical target samples, frequency weights, tap
budgets, and delay constraints across methods, so that every number quoted in the docs can
be regenerated with `just compare`.

## Phase 1: Design methods (Complete)

- [x] Alternating minimum-phase/linear-phase factor design in `mixedphase`
      (`DesignIterative`), plus a direct phase-interpolation baseline
      (`DesignPhaseInterpolation`), analysis metrics, tests, documentation, and a runnable
      CSV example.
- [x] Discrete-Hilbert-transform minimum-phase reconstruction alongside the real-cepstrum
      implementation; spectral-factorisation error, numerical sensitivity and runtime
      compared in `mixedphase/doc.go`.
- [x] Prescribed complex-response design with weighted least squares
      (`DesignComplexLeastSquares`), followed by a Lawson/IRLS path for peak-error control.
- [x] Direct magnitude-constrained, low-group-delay optimisation after Wu–Gao–Teo
      (`DesignLowGroupDelay`), with optimiser convergence and initialisation sensitivity
      documented — including the local minimum reached from a linear-phase start.
- [x] Hybrid IIR/FIR graphic EQ (`graphiceq`) as a structure-specific comparison for
      band-gain targets, kept out of the general mixed-phase API.

## Phase 2: Conditioning of the alternating correction loop (Planned)

Building the WebAssembly lab surfaced this and it blocks reproducible comparison, so it
comes before the benchmark suite.

`DesignIterative` with a nonzero delay is neither convergent nor platform-independent at
its default iteration count. On the 129-tap, 0.08-cutoff low-pass at delay 8, the RMS
magnitude error runs 5.37, 4.61, 4.92, 4.69, … 4.61 dB over passes one to six and then
_rises_ to 10.74 at the default twelve — the loop is past its best point, not converged, and
the `ToleranceDB` early stop never fires. Worse, native and WASM builds agree to ten digits
through four passes, differ in the fourth digit at six, and reach 10.74 against 15.83 at
twelve: the truncated-factor division amplifies rounding differences geometrically. The
other three methods are bit-identical across both builds, so this is specific to the
correction loop.

- [ ] Establish which pass count is actually best, and whether the divergence is inherent to
      the alternating scheme or an artefact of the regularised division (`Epsilon`).
- [ ] Make the early stop trigger on the error _rising_, not only on it settling.
- [ ] Add a cross-build determinism test (native vs `GOOS=js`) so this cannot regress silently.
- [ ] Re-derive the quoted comparison numbers once the loop is stable, and state which pass
      count produced them.

## Phase 3: Common benchmark and reference suite (Planned)

- [ ] Cover low-pass, parametric-EQ, crossover, deep-notch, and measured room-correction
      targets with one harness shared by all methods.
- [ ] Record magnitude error, group delay, pre-ringing/energy metrics, coefficient range,
      iterations, and runtime per method and target.
- [ ] Publish the results as a committed CSV plus a table in
      `docs/MIXED_PHASE_FILTER_DESIGN.md`, regenerated by a single command.

Exit criteria:

- [ ] All methods share one comparison harness and publish reproducible quality/runtime
      results under fixed tap and delay budgets.
- [ ] The docs state which method wins under which constraint, and where each one fails.

## Phase 4: Mixed Phase Lab (Planned)

A WebAssembly demo under `web/`, deployed to GitHub Pages.

- [ ] Method and delay controls driving the Go designs directly through WASM.
- [ ] Magnitude and group-delay plots (scaffolded).
- [ ] Impulse-response plot with the pre-ringing region marked.
- [ ] A/B transient playback so the pre-ringing is audible, not just plotted.
